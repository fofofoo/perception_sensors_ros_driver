# UWB 定位跟随系统通讯说明（D-PDOA-Node-B）

本文覆盖 **D-PDOA-Node-B 基站**的接入方式、物理连接、Modbus-RTU 协议与 ROS 节点接入。
基站通过 **TTL 串口 + Modbus-RTU** 主动输出标签坐标，配套标签为 D-PDOA-WATCH-B 手环、
D-DWM-PG2.3 / PG3.9 / PG4.9 模块。协议原文见
[PDOA 定位跟随系统手册](doc/PDOA_positioning_and_following_system_manual.pdf)。

| 项目 | 内容 |
| --- | --- |
| 基站型号 | D-PDOA-Node-B |
| 标签型号 | D-PDOA-WATCH-B、D-DWM-PG2.3、D-DWM-PG3.9、D-DWM-PG4.9 |
| 链路 | TTL UART（可经 USB-TTL 模块转 USB） |
| 协议 | Modbus-RTU，功能码 03H 主动上报定位帧 |
| 串口参数 | 115200，8 数据位，1 停止位，无校验（8N1） |
| ROS 节点 | [`uwb_rtu_serial_demo`](catkin_ws/src/uwb_rtu_serial_demo/README.md) |

> 旧 `serial_demo`、`control_demo` 包已移除，本仓库只保留 `uwb_rtu_serial_demo`。

---

## 1. 接入方式

### 1.1 方式 A：TTL 直连 USB-TTL 模块（ROS 节点默认）

```
 D-PDOA-Node-B 基站                USB-TTL 模块                 PC / ROS 节点
+-------------------+  Tx/Rx/GND  +---------------+   USB    +------------------------+
| TTL 排针           | <---------> | CH340/CP210x  | <------> | /dev/ttyUWB            |
| Modbus ID = 01     |             | TTL 电平      |          | uwb_node（115200 8N1） |
+-------------------+             +---------------+          +------------------------+
```

- 基站 Tx 接模块 Rx，基站 Rx 接模块 Tx，GND 共地；
- 只接收定位数据时基站 Rx 可以不接，但建议接上，方便用 40H 指令维护 K 列表；
- 模块必须是 **TTL 电平**，不能直接接 RS-232 电平；接线前确认模块电平与基站一致。

### 1.2 方式 B：经小车控制板 / D-Control（P-USB）

1. 基站连接端口接到小车控制板或 D-Control 板上对应的基站接口；
2. 将串口通讯开关拨到白色丝印 **P-USB** 一侧；
3. 用 Micro-USB 数据线连接控制板与 PC，PC 上出现 `/dev/ttyUSB*` 或 `/dev/ttyACM*`；
4. 打开上位机或串口助手，按 Modbus-RTU 指令操作。

该方式主要用于校准和配置；控制板同时占用串口时，ROS 节点无法再打开同一设备。

### 1.3 如何选择

| 现场条件 | 推荐方式 | 设备名 | 说明 |
| --- | --- | --- | --- |
| PC / 工控机直接接基站 | A：USB-TTL | `/dev/ttyUSB0` 或 udev 固定名 | 本仓库节点的默认方式 |
| 已装在智能小车上，走控制板 | B：P-USB | `/dev/ttyUSB*` / `/dev/ttyACM*` | 注意控制板是否已占用该串口 |
| 需要长距离、抗干扰 | 自备 RS-485/光纤转换 | 由转换器决定 | 手册未提供 RS-485 接口，需外接转换并确认电平 |

## 2. 物理连接与参数

### 2.1 接线

| 基站端子 | USB-TTL 模块 | 说明 |
| --- | --- | --- |
| Tx | Rx | 交叉连接 |
| Rx | Tx | 交叉连接；只收数据时可不接 |
| GND | GND | 必须共地 |
| 电源 | 按基站额定电压单独供电 | 不要从 TTL 排针取电 |

### 2.2 串口参数（手册 4.1）

| 项目 | 值 |
| --- | --- |
| 波特率 | 115200 |
| 数据位 | 8 |
| 停止位 | 1 |
| 奇偶校验 | 无 |
| 流控 | 无 |

### 2.3 从机地址（Modbus ID）

- 手册示例与出厂默认：`01`；
- 基站寄存器 0（`00H`）为基站 ID，可写范围 `0~7`；
- Modbus 地址码有效范围 `001~255`，本节点只接受 `1~247` 的应答帧头。

### 2.4 设备名、权限与 udev

默认设备名为 `/dev/ttyUWB`（launch 参数 `uwb_serial_port`）。若没有配置 udev，
启动时用 `uwb_serial_port:=/dev/ttyUSB0` 覆盖，或把
[launch/uwb_node.launch](catkin_ws/src/uwb_rtu_serial_demo/launch/uwb_node.launch)
中的默认值改成实际设备。

固定设备名示例（VID/PID 用 `udevadm info -a -n /dev/ttyUSB0` 查，不要照抄）：

```bash
# /etc/udev/rules.d/99-uwb.rules
SUBSYSTEM=="tty", ATTRS{idVendor}=="<VID>", ATTRS{idProduct}=="<PID>", SYMLINK+="ttyUWB"
```

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
```

串口权限：

```bash
sudo usermod -aG dialout $USER   # 重新登录后生效
```

## 3. 设备输出方式

**基站定位成功后自动输出坐标，PC 无需发送任何指令开启数据输出**（手册 4.4（1））。
因此本节点对串口只读不写。

输出频率由**标签配置**决定，不是由基站或节点决定：

| 标签状态 | 默认 | 可配范围 | 说明 |
| --- | --- | --- | --- |
| 动态（检测到运动） | 10 Hz（100 ms） | 0.1~20 Hz | 手环晃动后按动态频率发包 |
| 静态（静止休眠） | 0.1 Hz（10000 ms） | 0.05~20 Hz | 静止后可能长时间不发包 |
| 静态不休眠发包 | 100 ms | 50~65535 ms | 到达静态时间后补发若干包 |
| 报警模式 | 100 ms（10 Hz） | 50~65535 ms | 手环按 SOS 键进入 |

基站测距能力上限 **50 Hz**（手册参数表）。节点 30 Hz 轮询足以覆盖 10~20 Hz 的正常数据，
且每轮会把缓冲中已到达的帧全部取完。

**新标签必须先加入 K 列表**：基站只和 K 列表中的标签测距。检测到新标签时，基站只上报
一次新标签帧（`03 0A 40 AD ...`），需要用上位机或 40H 指令把 8 字节标签 ID 加入 K 列表，
之后才会输出定位帧。K 列表最多 10 个标签，断电不丢失（手册 3）。

## 4. 底层协议（Modbus-RTU）

### 4.1 03H 应答帧格式（手册 4.2）

```
 下标   0     1     2       3 ~ 2+LEN        3+LEN   4+LEN
 字段   ADR   03H   LEN     DATA             CRC低   CRC高
```

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| ADR | 1 | 从机地址，手册范围 001~255；本节点按 Modbus 规范接受 1~247 |
| 03H | 1 | 读寄存器功能码 |
| LEN | 1 | 后续寄存器数据字节数，**偶数**，定位帧为 `0x12`（18） |
| DATA | LEN | 寄存器数据，高字节在前 |
| CRC | 2 | CRC16，**低字节先发** |

整帧长度 = `3 + LEN + 2`。CRC 覆盖 **ADR 到最后一个数据字节**，不包含 CRC 本身。

CRC16 参数：

| 项目 | 值 |
| --- | --- |
| 初值 | `0xFFFF` |
| 多项式 | `0xA001`（`0x8005` 位反转） |
| 输出字节序 | 低字节在前 |

### 4.2 定位数据帧（LEN = 0x12，整帧 23 字节）

手册示例帧：

```text
01 03 12 CA DA 96 24 4B 6E 76 00 58 08 FF 55 00 38 00 B5 E8 EA 18 3E
```

逐字节解析：

| 字节（1 起） | 偏移（0 起） | 内容 | 示例 | 换算 / 说明 |
| --- | --- | --- | --- | --- |
| 1 | 0 | Modbus ID | `01` | 基站地址 |
| 2 | 1 | 功能码 | `03` | 读寄存器 |
| 3 | 2 | 数据长度 | `12` | 18 字节 |
| 4~5 | 3~4 | 定位标识 | `CA DA` | 定位帧标志 |
| 6~13 | 5~12 | 标签 64 位 ID | `96 24 4B 6E 76 00 58 08` | 低字节在前；`08 58` 表示手环、软件 V5.8 |
| 14~15 | 13~14 | X 坐标 | `FF 55` | 有符号，cm → **-171 cm = -1.71 m** |
| 16~17 | 15~16 | Y 坐标 | `00 38` | 有符号，cm → **56 cm = 0.56 m** |
| 18~19 | 17~18 | 测距 | `00 B5` | **无符号**，cm → **181 cm = 1.81 m** |
| 20~21 | 19~20 | 角度 | `E8 EA` | 有符号，1/100 度 → **-59.10°** |
| 22~23 | 21~22 | CRC16 | `18 3E` | 低字节 `18` 在前，CRC 值 `0x3E18` |

CRC 手工验算：对
`01 03 12 CA DA 96 24 4B 6E 76 00 58 08 FF 55 00 38 00 B5 E8 EA`
计算得 `0x3E18`，发送顺序为 `18 3E`，与示例一致。

> 手册解析表把测距字段印成 `00 91`（181），但示例帧实际字节是 `00 B5`（181），
> 两者数值相同、字节不同。以帧内字节和 CRC 为准，`00 91` 是手册笔误。

### 4.3 新标签上报帧（LEN = 0x0A）

```text
01 03 0A 40 AD 96 24 4B 6E 76 00 58 08 AD 8D
```

| 字节（1 起） | 内容 | 示例 | 说明 |
| --- | --- | --- | --- |
| 1~3 | ADR / 03H / LEN | `01 03 0A` | 数据长度 10 |
| 4~5 | 新标签标识 | `40 AD` | 与定位帧的 `CA DA` 区分 |
| 6~13 | 标签 ID | `96 24 4B 6E 76 00 58 08` | 低字节在前 |
| 14~15 | CRC16 | `AD 8D` | |

该帧只在基站第一次监听到标签时上报一次。节点会丢弃它，不发布到话题。

### 4.4 添加 / 删除 K 列表（40H）

| 操作 | 指示标志 |
| --- | --- |
| 添加标签 | `4A 4E` |
| 删除标签 | `4A DE` |

删除示例（手册 4.4（3））：

```text
发送：01 40 0A 4A DE 96 24 4B 6E 76 00 58 08 F9 A4
应答：01 40 04 4A DE 00 01 43 22
```

应答中 `00 01` 表示成功，`00 00` 表示失败。添加时把指示标志换成 `4A 4E` 并**重新计算 CRC**，
不要照抄删除帧的 CRC。该指令需要在基站 Rx 上写入，本节点当前只读，未实现下发。

### 4.5 其它功能码

| 功能码 | 用途 | 手册章节 | 本节点 |
| --- | --- | --- | --- |
| 03H | 读寄存器 | 4.2 | 解析应答 |
| 06H | 写单个寄存器 | 4.2 | 未实现 |
| 10H | 写多个寄存器 | 4.2 | 未实现 |
| 40H | 添加 / 删除 K 列表 | 4.4（3） | 未实现 |
| 50H | 下发标签配置 | 4.4（5） | 未实现 |

## 5. 通信库

本节点使用 ROS 自带的 [`serial`](http://wiki.ros.org/serial)（`ros-noetic-serial`）：

| 能力 | `serial` 库 | 说明 |
| --- | --- | --- |
| 打开 / 配置串口 | 提供 | 8N1、波特率、超时 |
| 字节收发 | 提供 | `available()` / `read()` / `write()` |
| 分帧 | **不提供** | 需要自己按帧头 + LEN + CRC 同步 |
| CRC | 不提供 | 本节点实现了 Modbus-RTU CRC16 |
| 断线检测 | 不提供 | 由应用层心跳判断 |

历史方案（未采用）：

- **把一次 `read()` 的返回值当一整帧**：USB 串口会把一帧拆成多次到达，也会把多帧粘在一起，
  该做法会丢帧或解析错位，已废弃；
- **`libmodbus`**：适合主从问询，但本设备是主动上报，接入收益低，未采用。

## 6. 中介设备

| 设备 | 作用 | 是否转换协议 | 注意事项 |
| --- | --- | --- | --- |
| USB-TTL 模块（CH340 / CP210x 等） | TTL ↔ USB | 否，纯电平转换 | 确认 TTL 电平匹配；驱动安装后出现 `/dev/ttyUSB*` |
| 小车控制板（P-USB 档） | 基站串口转 USB | 否 | 串口开关必须拨到 P-USB；控制板可能占用串口 |
| D-Control 板 | 基站接口转 USB | 否 | 同上，主要用于校准与上位机配置 |

本项目没有网络网关、没有 Modbus TCP 转换，链路始终是 **Modbus-RTU over TTL**。

## 7. 问询流程

正常运行时**没有问询**，基站按标签配置的频率主动推送：

```
 基站                         USB-TTL / 控制板                ROS 节点（uwb_node）
  |  每 100 ms（动态默认 10 Hz）    |                              |
  |-- 01 03 12 CA DA ... ------->|-- 字节流 ------------------->| RtuClient 累积到缓冲
  |                              |                              | 找 ADR+03H+偶数 LEN
  |                              |                              | CRC16 校验
  |                              |                              | UwbNode 过滤 CA DA
  |                              |                              | 解码 cm / 0.01° -> m / 度
  |                              |                              | 每帧 publish 一次
```

只有维护 K 列表、改基站寄存器、下发标签配置时才需要上位机发请求：

```
PC --> 01 40 0A 4A 4E <标签ID8字节> <CRC> --> 基站
PC <-- 01 40 04 4A 4E 00 01 <CRC> --------- 基站
```

## 9. ROS 节点实现简介

文件职责、参数、话题语义与已知限制见
[功能包 README](catkin_ws/src/uwb_rtu_serial_demo/README.md)。这里只给数据流：

```
 串口字节流
    |
    v
 RtuClient（无 ROS）      累积缓冲 -> 找帧头 -> CRC16 -> 整帧
    |
    v
 UwbNode（无 ROS）        23 字节 + 03H + LEN=0x12 + CA DA -> 解码
    |
    v
 main.cpp（ROS）          advertise("uwb_position", 10) -> publish
```

设计要点：

- 通讯层（成帧、CRC、心跳）独立成无 ROS 依赖的 `rtu_client` 库；
- 发布器、话题名、30 Hz 循环只在 `main.cpp`，节点类不碰 ROS 拓扑；
- 串口只读，不发送任何问询；基站主动推送；
- 每收到一帧发布一帧，不用定时器重发旧帧。

## 10. 排障记录

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 节点启动报「串口打开失败」 | 设备名不存在 | 启动时加 `uwb_serial_port:=/dev/ttyUSB0`，或配置 udev |
| 报 `Permission denied` | 用户不在 `dialout` 组 | `sudo usermod -aG dialout $USER`，重新登录 |
| 报 `Device or resource busy` | minicom、上位机或控制板已占用串口 | 关闭占用进程后重启节点 |
| 收不到任何帧 | Tx/Rx 未交叉、未共地、模块不是 TTL 电平、基站未上电 | 按 2.1 节重接；用示波器/串口助手确认 |
| 只看到 `03 0A 40 AD ...`，没有定位帧 | 标签不在 K 列表 | 用上位机或 40H（`4A 4E`）把标签 ID 加入 K 列表 |
| 标签静止后长时间没数据 | 静态休眠，默认 10 s 才发一包 | 等待；或把标签静态频率调小；节点 15 s 才告警 |
| 话题频率只有 0.1 Hz | 标签处于静态休眠 | 确认标签动态/静态频率配置，不是节点丢帧 |
| 话题频率不是固定 10 Hz | 话题跟标签发包走，标签会动态/静态/报警切换 | 属正常；需要固定频率请在上游处理 |
| `fre` 字段第一秒为 0 | 1 秒心跳窗口尚未结算 | 正常，第二秒起有值 |
| 数据偶发错位、跳变 | 半帧 / 粘包 / 垃圾字节 | 本节点已做字节流分帧与 CRC 重同步；仍异常查线长、接地、USB 供电 |
| 距离显示成负数 | 旧代码用有符号解析测距字段 | 本节点已改为无符号；确认运行的是新节点 |
| X/Y 方向与预期相反 | 基站坐标系定义与直觉不同 | 见 4.2 与包 README 的「数据语义」；需要时在上游做坐标变换 |
| 角度跳变较大 | 角度精度 ±5°，多径、遮挡、未校准 | 按手册 5.3 做基站校准；保证正面可视 |
| 拔插 USB 后设备名变了 | Linux 重新枚举 | 配置 udev 固定名称 |
| `rosrun` 找不到包 | 没有 source 工作空间 | `source devel/setup.bash` |

## 11. 遗留问题

| 位置 | 问题 | 影响 |
| --- | --- | --- |
| `uwb_node.cpp` | 不解析标签 ID（偏移 5~12） | 多标签场景无法区分来源 |
| `main.cpp` | 运行中串口断开不自动重连 | 需重启节点 |
| `main.cpp` | 轮询频率、心跳阈值写死在源码 | 改这两个值需重新编译（串口与打印开关已进 launch） |
| `uwb_data.msg` | 没有 `header` 字段 | 无精确时间戳和坐标系标识 |
| `rtu_client.cpp` | 只接受 03H 应答帧 | 若将来下发 40H/50H，应答不会被取出 |
| `uwb_node.cpp` | 不做坐标变换、滤波、平滑 | 输出是基站本地原始坐标 |
| 硬件 | 基站背面无法得到正确坐标 | 安装时让标签处于基站正面 120° 范围内 |
| 手册 | 定位帧示例的测距字段印为 `00 91` | 与示例帧 CRC 不符，实际为 `00 B5`（181 cm） |

历史方案（未采用）：

- 100 Hz 轮询串口：对 10~20 Hz 数据没有必要，已降为 30 Hz；
- 用有符号数解析测距字段：距离大于 327 m 会变负，已改为无符号；
- 定时器按固定频率重发上一帧：下游会把旧值当新数据，已改为收一帧发一帧；
- 把一次 `read()` 当一整帧：会丢帧/错位，已改为字节流分帧。
